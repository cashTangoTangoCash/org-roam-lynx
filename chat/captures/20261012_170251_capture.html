How it behaves

  • i: inserts [[id:UUID][Title]] followed by a space at point in Emacs.
  • I: does the same, followed by a newline.
  • Any row: both keys work on the highlighted row, including MAIN, and don't move the cursor. In my UI test, i on MAIN and then I on a BIDIR row put exactly the expected text into the Emacs buffer. Pressing i, moving down, and pressing i again chained two links in order.
  • No focus change: Emacs isn't raised, so you can keep pressing i or I from the terminal. The footer confirms where the link went, for example Inserted link to "Alpha" in Emacs buffer target.org.
  • Undo: each insert is one normal edit, so a single undo in Emacs removes it.

Which Emacs buffer gets it It's the buffer in Emacs's selected window, which is the one you were last working in. If a minibuffer prompt is open, it goes to the window you came from. If that buffer is read-only (a dired or org-roam buffer, say), nothing is inserted and the footer shows emacsclient failed: Buffer is read-only: .... A stopped server or a missing emacsclient also shows a plain message.

Design choices

  • Emacs builds the link, with org-link-make-string, the function org-roam's own insert command uses. The title comes from org-roam inside Emacs when it knows the node. Our database copy is only a fallback. This avoids encoding trouble, and non-ASCII titles, quotes, and backslashes all came through intact in the tests.
  • Brackets in titles: a title like Array [0] and [[x]] gets invisible zero-width characters before the closing brackets. That's standard Org behavior, there so the link doesn't end early.
  • Refactor: e and the new keys now share one emacsclient helper, so error handling is identical.
  • Footer: to fit 80 columns with i/I:Link, I shortened l:Jump here to l:Jump and dropped the MAIN-specific e wording.

Things to know

  • A link inserted this way isn't in org-roam's database until Emacs saves that buffer and syncs, so press r here afterward to see it appear as an IN row.
  • I tested against a stand-in for org-roam's org-roam-node-from-id and org-roam-node-title, not the real package. The change to e was also only checked by a UI run and error paths, not against your org-roam. Try both once on your real setup.
  • Not tested: the open-minibuffer case and several GUI frames. In the multi-frame case it should use whichever frame Emacs considers selected.
