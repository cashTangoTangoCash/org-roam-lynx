**What `?` does**
- **Conversion:** it converts `README.md` to HTML with pandoc, as GitHub-flavored Markdown.
- **Where it's written:** it saves the HTML as `org-roam-lynx-help.html` in a private per-user directory (`$XDG_RUNTIME_DIR`, else `/tmp/org-roam-lynx-<uid>`). It overwrites that file each time, so nothing piles up.
- **Opening it:** it opens the page in eww and raises the Emacs frame. It opens at the "Reading the screen" heading rather than the top, so the legend and key table are first. Scroll up for the rest.
- **Closing it:** press `q` in eww to return to your previous buffer.

**What I added to make your scheme hold up**
- **Finding the README:** it looks next to the real script (following symlinks), then at `$ROAM_LYNX_README`, then in `~/.local/share/org-roam-lynx/`. Your current install copies only the `.py` file into `~/.local/bin`, so help would say "README.md not found". Installing by symlink fixes that, and `git pull` then updates the script too: `ln -s "$PWD/org_roam_lynx_browse_graph.py" ~/.local/bin/`.
- **Images:** the generated HTML sits in a temp directory, so I added a `<base>` tag pointing at the README's folder. I traced Emacs's URL expansion, and your GIF and screenshots resolve to `docs/...` in the repo.
- **No pandoc:** it opens `README.md` as read-only text in Emacs instead of failing.
- **Other failures:** a missing README, a stopped Emacs server, and a hostile symlink planted where the temp directory should be each give a clear one-line message.

**Things to know**
- **Insert after help:** while the eww help buffer is the selected window in Emacs, `i`/`I` will fail with "Buffer is read-only". Press `q` in eww first.
- **Heading name:** the landing spot depends on the README heading "Reading the screen". If you rename it, change `HELP_ANCHOR` near the top of the script.
- **Without Emacs:** browsing still works, but `?` shows an error, since help needs Emacs. A tiny in-terminal key list would help there, but it would duplicate content, so I left it out.
- **Not tested:** I couldn't see images render, because the sandbox Emacs has no GUI. I confirmed the paths resolve, but whether your GUI eww shows the GIF and JPGs is worth a look.
